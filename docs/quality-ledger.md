# Quotient hardening ledger

Living record of the UX, evidence-integrity and reliability work. Status words are used strictly:
**verified** = reproduced before and checked after in the running app or by a test that fails without the fix;
**implemented** = changed and covered by a test or typecheck, not yet exercised end to end;
**open** = known, not fixed; **blocked** = needs a decision or a dependency.

Baseline: branch `main`, HEAD `20b8c7c`, plus ~50 uncommitted working-tree files from earlier work (treated as authoritative; nothing was reverted).
Local topology: portal `:3000` (Next dev), MCP API `:8080` (uvicorn, in-process worker port), MinIO container `engine-minio-1` `:9000`, bucket `axion-meeting-local`, ledger `.local/run/meetings.json`. Worker reads media from `derivatives/<object_key>` on disk and uploads a playback copy to MinIO.

## Changes (all in working tree, uncommitted)

### Backend / worker
- `apps/worker/loop/quality.py`: fallback action no longer sends `origin` unless the loaded schema declares it, and a rejected draft is skipped, not fatal (**verified**: new test runs against shipped contracts). Coverage stage rewritten: code-derived uncovered set is authoritative, contract-shaped payloads, 20-span supplement batches with unique claim ids (**implemented**, test `test_coverage_and_supplement_payloads_match_their_contracts`). Extraction continues after a failed window and stops after 3 consecutive failures; entailment skipped when no span contains the quote (**implemented**, tests). Lens failure returns `not_evaluated` (**implemented**, test).
- `apps/worker/sonic/client.py`: a rejected transcription segment is retried once on a fresh session (partial text dropped), then recorded as an `untranscribed` span; the quality loop turns it into a coverage gap, so the meeting finishes in review with the missing part named instead of failing (**implemented**, 2 tests; **not yet exercised against the live service**: the API must be restarted to load it, and a restart would have discarded the benchmark running at the time). The portal shows "Not transcribed" in the transcript and the To check list.
- `apps/worker/bedrock/wire.py`: writes wait for socket writability (`_send_all`), 2 tests. `apps/worker/sonic/client.py`: a segment rejected by the content filter is re-run in 90 s windows so only the rejected window is lost; per-session failures are logged. `apps/worker/quotient/port.py`: local playback signs the per-meeting upload when present (3 tests). **All three implemented and unit-tested; live verification pending the next restart** (restarting would have discarded in-flight runs).
- `apps/worker/graph/lenses.py`, `publish.py`, `quotient/port.py`, `apps/api/quotient/worker/memory.py`: `not_evaluated` dimension state persisted; blocks `ready`.
- `apps/api/quotient/graph/gate.py`: dimension rows carry `state` (`findings` | `none_in_transcript` | `not_evaluated`) and `held_findings` on none rows; any `not_evaluated` lens blocks `ready` (**implemented**, 2 API tests). **Contract change is additive**; `withheld` semantics and `MCP.md` are unchanged.
- `scripts/bench_meeting.py`: reusable benchmark harness (submit, poll, record graph + summary).

### Portal (`apps/web`)
- New presentation layer `lib/present.ts` (one map per contract enum; unknown values fall back to neutral wording, never the raw code) and `lib/insights.ts` (charts derived only from stored entities). 13 unit tests (`npm test`).
- Rewritten: Brief (partial-brief notice, evidence on click), Key points (topic tabs, "Not mentioned in the video" only when the lens looked and found nothing; otherwise "N points not yet confirmed" / "could not be analysed"), Transcript (one searchable conversation, original wording on demand, corrections report real failures), To check (grouped by reason, repeats merged), Insights (4-5 purpose-built charts with table views), Status (plain steps, confirmed stop), Downloads, evidence panel (only when something is selected).

- Removed from ordinary view: timeline strip with seam/coarse markers, speaker-hypothesis table, raw/synthesized dual panes, aggregation names, worker ids. Underlying data and exports are untouched.
- Smaller fixes: loading states, "Remove from list" confirmation, home list no longer drops rows past 20, settings and navigation wording.

### Local storage (approved by the user)

## Open / blocked
- Content-filter rejection of one 90 s window of the real recording (900-990 s) is deterministic and cannot be recovered; it is named as "Not transcribed". Cause is on the provider side.
- 11-13% of speech spans end with no claim, gap or omission; the supplement answers every batch but not every span, and the API and worker still define coverage differently.
- Auto-accepted model actions: an action with a resolved owner span is stored `accepted` without a person; the UI now says "Owner stated in the recording" for those. Whether that should stay `proposed` is a product decision.
- Speaker attribution is absent on all runs (0 spans attributed), so every line reads "Unnamed speaker".
- No automated accessibility audit; no keyboard-only walkthrough.
- Review items cannot be resolved by a person (no tool). Product decision needed before building one.
- Quote resolution requires a single span; 84% of Sonic spans end mid-sentence, so many claims lose their citation. Fixing this changes the citation model; deferred pending real-content numbers.
- `numeric_failed` is never produced by the worker; `gap` is collapsed into `unresolved` by the API.
- Cancel does not stop in-flight model calls; restart re-runs all queued/working rows from scratch.
- The Assistants page (formerly "MCP") still shows connection headers; it is an integration screen by design.

## "+ Context", the duplicate upload row, and software-architecture analysis (2026-10-09)

**What was built.**

## Adversarial check of the read-time filters (2026-10-09, no model calls)
Fed the `gate.py` commentary filter and the first-person promise pattern ordinary English a lecture or a negotiation would contain.
- **Found:** the commentary filter removed whole sentences that were content, not transcript mechanics ("the line labelled Q3 in the chart, which rose 12%", "in the following turn of the protocol handshake", "the continuing argument over funding"), so a lecture about charts or code would lose real items. The promise pattern read refusals as promises ("I can't make Friday", "We will not do that") and so could bind an action to its speaker, and it missed "I'm gonna" and "We're going to".
- **Fixed:** positional wording (continuing argument, in the next line, from the previous segment) now counts as commentary only when the same clause also names a speaker; the unambiguous marks (span ids, "line labelled Speaker 3") still go. The promise pattern in `gate.py` and `worker/graph/digest.py` excludes "n't", "not" and "never" after the verb and accepts the "'m/'re gonna/going to" contractions and curly apostrophes.
- **Pinned by:** `test_positional_wording_is_removed_only_when_it_is_about_the_transcript_and_a_refusal_is_not_a_promise` (API) and `test_a_refusal_is_not_a_first_person_promise_and_a_contraction_is` (worker).
- **Not measured on a live run.** The effect on the Round 13 numbers is expected to be small; it removes false drops and false owners rather than adding content.
- **Second finding, same check (due phrases):** the time-word test that decides whether a due phrase is shown (`_due` in the worker, `dueText` in the portal) rejected real deadlines: "next sprint", "by noon", "ASAP", "in a fortnight", "by midnight", "immediately". It still rejects names and conditions ("Lee", "once approved", "after the demo"). Added sprint, noon, midnight, midday, overnight, fortnight, ASAP, immediately and "right away" in both places, and the refusal-safe promise pattern in the portal copy too (it had the same "I can't" bug). Pinned by the worker test `test_a_due_phrase_needs_a_time_word_but_not_only_a_weekday_or_number` and the web `digest.test.ts` assertions.
- **Third finding, same check (malformed model output):** a seeded fuzz (5 seeds x 4,000 cases per function, 12% of fields replaced by numbers, booleans, NaN, nested lists, unhashable objects, or deleted) over the worker's `ground_digest` and the API's read-time `_digest`.
  - **Worker:** crashed when `positions` (a disagreement's sides) was a number, boolean or string, which would have lost the whole digest for that meeting. `_clean_item` now turns any non-list `positions` into an empty list.
  - **API:** the read-time check crashed on damaged stored rows (non-list `span_ids`, an unhashable or list-valued `assignee`, a list-valued `answer_span_id`), which would have stopped the meeting opening. It now reads such fields as empty and drops only the damaged row. The worker writes well-formed digests, so this needs a damaged or hand-edited ledger, but the cost of a crash there is the whole meeting.
  - **After the fixes:** 0 crashes on both over the same seeds. Pinned by `test_a_model_that_sends_positions_as_a_number_or_text_cannot_lose_the_digest` (worker) and `test_a_damaged_stored_digest_loses_the_damaged_rows_and_never_the_meeting` (API). The fuzz harness itself is a scratch script, not in the repo.
- **Same fuzz on the portal:** `parseDigest` and the helpers that read it (`hasOutcomes`, `chapterAt`, `dueText`, `promisedByOwner`, JSON round trip) over 5 seeds x 4,000 mutated digests: 0 crashes. The parser was already defensive; no change.
- **Fuzz of the MCP surface through the real HTTP app (no model):** 3,000 requests against a seeded ready meeting: every tool with 15% of its arguments replaced by junk (null, numbers, booleans, 5,000-character strings, path traversal, NUL, emoji, nested lists, huge integers), an unknown or non-string tool name, and random methods (tools, resources, prompts, tasks, ping) with junk params. Outcomes: 293 ok, 70 tool errors, 2,024 protocol errors, 613 event-stream bodies. **0 responses that were not 200/202, 0 containing a traceback, a file path or an exception name.** No change needed. Scratch harness, not committed.

## Hostile context files and hidden text (2026-10-09, no model calls)
- **Converter:** fed ten hostile files through the real converter (random bytes named `.pdf`, an empty `.docx`, a fake `.xlsx`, a NUL-laden `.md`, a 50 MB single line, a 100,000-column CSV, a 200 MB-uncompressed zip-bomb `.docx`, a 200-character file name, a BOM CSV, a right-to-left-override text). Every one either converted or failed with a plain sentence in under a second; peak child memory 161 MB. No change needed there. **Still open:** a hard memory limit (`RLIMIT_AS`) cannot be checked on macOS, which does not enforce it, so it was not added blind; do it on the Linux host with a measured ceiling.
- **Found:** nothing removed invisible text. The Unicode Tags block (U+E0000 to U+E007F) is invisible in most viewers and is a known way to hide instructions in a document a model reads; bidirectional overrides and isolates reorder what a person sees. Both passed through to the model, and to the portal in a file name.
- **Fixed:** `context/convert.py clean` (the single exit for plain, CSV, JSON and converted text) removes the Tags block and U+202A to U+202E and U+2066 to U+2069. Joiners and the left/right marks stay (Persian, Indic, Arabic and emoji need them). The loader also cleans a cached conversion on the way out, so entries cached before this change are covered. The API strips the same characters and control characters from a context file name and refuses a name that is only such characters.
- **Pinned by:** `test_text_a_person_cannot_see_but_a_model_reads_is_removed_and_real_scripts_are_kept`, `test_a_conversion_cached_before_the_cleaning_rule_is_cleaned_when_it_is_read_back` (worker) and `test_a_context_file_name_loses_hidden_and_direction_override_characters` (API).
- **Not done:** the same characters can arrive in a meeting's own spoken transcript only through the speech model, so no strip was added there; a person's typed purpose and notes are their own text.
- **Oversized payloads through the real HTTP app:** a 1,000,000-byte request cap (`server.py _MAX_BODY`) answers 413 before buffering (a 60 MB body took 0.07 s, an 8 MB and a 30 MB edit under 0.05 s); a span edit of 100 KB to 900 KB inside the cap gets "text is too long"; every oversized field (speaker name, title, purpose, edit text) was refused.
